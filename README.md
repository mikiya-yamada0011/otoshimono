# 落とし物システム

## 現行仕様（2026-10-19）

拾得者の登録・ありがとう・お礼メール・公開状態の選択・学生申告の手動照合を廃止。連絡先が分かる品物と旧非公開品は表示しない。個別登録は原則7日で警察へ移管する品物、写真掲載は3か月で処分する品物に整理した。写真は窓口×受付日で3枚まで、写真0枚の枠は一覧から除外。紛失キャンパスは主検索行の左に常時表示する。

[変更・検証・反映手順](../lost-found-verification/2026-10-19_運用仕様の整理.md)。学生パッケージは2.14.0.0。職員版は運用変更と写真圧縮を維持し、写真1枚ごとの標準フォーム直接保存へ切り替えて公開済み。関連フロー4本を更新し、廃止フロー2本を停止した。学生版は利用者の指示によりローカルで確認する扱いで、クラウド未展開。以下の過去の記録よりこの仕様を優先する。

## 写真の新しい保存形式（2026-10-19）

`LFDailyPhotoBatches` の1行を1写真として読み、公開完了フラグと実際の添付を確認して窓口×受付日でまとめる。保存枠は1〜3、画像は各行1枚。旧親添付と子画像のマニフェストへのフォールバックは撤去した。実APIで3枚の読込を確認し、Repository・業務検証、画面テスト61件、本番ビルドが成功した。[公開・検証記録](../lost-found-verification/2026-10-19_写真保存の新方式公開.md)。

## 品物ごとの案内と登録カテゴリ（2026-10-12）

「探す」は「財布・電子機器など」と「傘・衣類・かばんなどの写真」で切り替える。各画面で対象品物を説明し、写真の掲載は毎日必須ではないことも表示する。写真は引き続き窓口×受付日で保存し、同じ受付日の複数窓口を一つの枠にまとめる。

新しい個別登録・学生の検索条件・学生の新規紛失登録は、財布／現金、主要電子機器（有線・無線イヤホンを含む）、時計／アクセサリー、薬、楽器、カード／証明書、鍵、印鑑の28カテゴリを基本とする。学生の拾得物フォームも同じ選択肢を使い、一般品は窓口への届け出を案内する。職員デモは、記名・高額・個人情報がある一般品を明示的に例外として選べるが、新規例外品は非公開とする。自転車・移動関連用品は新規の選択肢に出さない。

共通の選択ポリシーは `src/webparts/lostFoundStudent/found-items/data/registration-policy.json`。カテゴリ辞書全体や既存レコードは削除しない。過去の一般品の一覧・受取申込み・履歴、既存の紛失登録の編集は継続できる。これは新しい画面の選択肢の変更であり、既存SharePointデータの一括移行やカテゴリマスターの削除は行わない。

受付・手動返却として実装した学生向けSPFxアプリ。職員はPower Appsを使用する。

## 画面の確認内容

| 学生用SPFx・スマホ                                     | 職員用Power Apps・PC                             |
| ------------------------------------------------------ | ------------------------------------------------ |
| 学校メールの必須登録                                   | 開閉できる左側メニュー                           |
| 通常品の一覧・詳細・条件検索                           | 拾得物登録・編集・保管中一覧                     |

| 新着案内・貴重品の個別案内                             | 貴重品の現物を確認して本人へ案内                 |
| 任意の特徴入力・受取申出・取り下げ                     | 「受取対応」で学籍番号・メール・受付番号から検索 |
| 受取窓口・受取番号・返却履歴                           | 本人確認後の手動返却・来訪者への直接返却         |
| 任意の拾得物届け出・本人の届け出履歴                   | 返却記録の訂正、一括移管、メール送信状況         |

- QRは扱わない。一般品の写真掲示は個別の拾得物とは別に表示する。写真からの受取申込みは行わず、本人確認は職員が対面で行う。
- 色は複数選択。選択色の**どれか1色**が共通すれば検索・新着照合の対象になる。既存の単色データも読める。
- 保管場所は公開し、長い名称も折り返す。職員設定の窓口を次回登録と一覧・受け取り申し込みの絞り込み初期値にする。全窓口にも切り替え可能。
- 特徴は任意入力。学生の本人確認用特徴、内部メモ、連絡先は公開用リストへ複製しない。
- 公開可否は品物の種類で自動決定せず、職員が拾得物ごとに判断する。非公開品の個別案内では受取窓口と一般的な連絡文だけを本人へ示す。
- 条件保存時には既存品を照合しない。新しい拾得物登録時に、先に保存されていた条件を照合する。通知では紛失開始日以降の拾得物を対象にする。
- 返却時は既存の `Status / ReturnRecipientEmail / ReturnedAt / ReturnedByEmail` を更新。競合はSharePointのETagで検出する。
- 公開・通知の更新に失敗しても主記録は残し、画面に保存済みと再同期の案内を表示する。再同期では通知を重複作成しない。
- 学生の拾得物登録は必須ではない。学生が登録する場合は現物を窓口へ届けてから。メールは自動記録し、お礼の受信チェックは初期オン・不要ならオフ。職員も登録でき、希望者だけ拾得者メールを任意登録する。返却後のお礼は固定メールのみ。自由記述・匿名公開は廃止し、旧投稿データは非公開で保持する。

## 一般品の写真掲示（2026-10-11追加・10-12表示更新）

閲覧・拡大できます。公開中の旧方式は `LFDailyPhotoBatches` の添付から取得し、
個別品の照合・受取申込とは分離しています。種類ごとの写真登録は不要です。
同じ受付日は一つの枠にまとめ、その中を掲載窓口ごとに区切って表示します。
日付は新しい順で、窓口・受付日の絞り込み後も同じ日付の枠は重複しません。
未接続や権限不足は空一覧として隠さず、エラーと再試行を表示します。

1画像1レコード・標準機能のみの保存方式を実装し、登録・追加・削除・競合・画像の原本一致を検証しました。
写真の保存ではPower Automateやカスタムコネクタを呼びません。既存業務の他のフローは別です。
