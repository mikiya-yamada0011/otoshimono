# 落とし物システム

受付・手動返却として実装した学生向けSPFxアプリ。職員はPower Appsを使用する。

## SharePointに接続して開発する

Node.js 22.14以上・23未満。

```bash
npm install
npm start
```

`config/serve.json` の検証用SharePoint Hosted Workbenchが開く。大学のMicrosoft 365アカウントでサインインし、「落とし物システム」Webパーツを追加して確認する。読込・登録先は実際のSharePointリストなので、検証用サイトを指定する。

## 画面の確認内容

| 学生用SPFx・スマホ                                     | 職員用Power Apps・PC                             |
| ------------------------------------------------------ | ------------------------------------------------ |
| 学校メールの必須登録                                   | 開閉できる左側メニュー                           |
| 通常品の一覧・詳細・条件検索                           | 拾得物登録・編集・保管中一覧                     |
| 「紛失した物」で紛失申告・候補・受取予定をまとめて確認 | 学生の紛失申告の確認                             |
| 新着案内・貴重品の個別案内                             | 貴重品の現物を確認して本人へ案内                 |
| 任意の特徴入力・受取申出・取り下げ                     | 「受取対応」で学籍番号・メール・受付番号から検索 |
| 受取窓口・受取番号・返却履歴                           | 本人確認後の手動返却・来訪者への直接返却         |
| 任意の拾得物届け出・本人の届け出履歴                   | 返却記録の訂正、一括移管、メール送信状況         |

- QR・写真は扱わない。本人確認は職員が対面で行い、確認チェック後に返却を記録する。
- 色は複数選択。選択色の**どれか1色**が共通すれば検索・新着照合の対象になる。既存の単色データも読める。
- 保管場所は公開し、長い名称も折り返す。職員設定の窓口を次回登録と一覧・受け取り申し込みの絞り込み初期値にする。全窓口にも切り替え可能。
- 特徴は任意入力。学生の本人確認用特徴、内部メモ、連絡先は公開用リストへ複製しない。
- 公開可否は品物の種類で自動決定せず、職員が拾得物ごとに判断する。非公開品の個別案内では受取窓口と一般的な連絡文だけを本人へ示す。
- 条件保存時には既存品を照合しない。新しい拾得物登録時に、先に保存されていた条件を照合する。通知では紛失開始日以降の拾得物を対象にする。
- 返却時は既存の `Status / ReturnRecipientEmail / ReturnedAt / ReturnedByEmail` を更新。競合はSharePointのETagで検出する。
- 公開・通知の更新に失敗しても主記録は残し、画面に保存済みと再同期の案内を表示する。再同期では通知を重複作成しない。
- 学生の拾得物登録は必須ではない。学生が登録する場合は現物を窓口へ届けてから。メールは自動記録し、お礼の受信チェックは初期オン・不要ならオフ。職員も登録でき、希望者だけ拾得者メールを任意登録する。返却後のお礼は固定メールのみ。自由記述・匿名公開は廃止し、旧投稿データは非公開で保持する。

## 実環境の状況（2026-09-19）

検証サイトに8リストと追加5列を作成済み。実際の `FoundItems` **13件（保管中11件）**を新しい読込処理で取得し、更新競合に使うETagも確認した。一時的な利用者設定データで作成・更新・古いETagの拒否・削除も実環境で確認済み。既存13件の拾得物レコードは変更していない。

**学生への公開は未実施。** 現在の検証アカウントでは、リスト権限設定がREST・Chromeの管理画面ともに拒否された。作成したリストのアクセス権はまだサイトからの継承状態。所有者による権限設定、アプリカタログへの配置、Power Automateの接続・有効化が残る。

Power Automate用の5つの定義（公開情報同期・非公開品の本人案内、メール送信、感謝の公開、Power Apps登録時の条件照合、返却反映）は `deployment/flows` に生成済みで、検証環境へ配置・有効化した。公開・非公開の切替による`LFPublicItems`の作成／削除、メールキューの`PENDING`から`SENT`への遷移を実環境で確認済み。**本番用の通知ごとの閲覧権限と、更新した職員アプリ本体の既存アプリへの反映は未完了。** 

## リポジトリ構成

- `src/webparts/lostFoundStudent/app`：本番の学生画面、業務モデル、SharePoint接続
- `src/webparts/lostFoundStudent/found-items/data`、`utils`：現行画面で共有する分類・場所・公開判定
- `tests`：ブラウザ内保存を使う自動テスト専用コード
- `deployment`：SharePointリストとPower Automateの定義・配置手順
- `scripts`：ビルド可能なテストハーネスと検証コマンド

旧画面実装、ローカルのPower Apps操作スクリプト、認証状態、実行結果、ビルド生成物、`.sppkg`、`.msapp`はGit管理しない。
