# 落とし物システム（QRなし版）

QRを使わない受付・手動返却として実装した学生向けSPFxアプリ。職員はPower Appsを使用する。

## SharePointに接続して開発する

Node.js 22.14以上・23未満。

```bash
npm install
npm start
```

`config/serve.json` の検証用SharePoint Hosted Workbenchが開く。大学のMicrosoft 365アカウントでサインインし、「落とし物システム」Webパーツを追加して確認する。読込・登録先は実際のSharePointリストなので、検証用サイトを指定する。リスト、権限、SPFxパッケージ、Power Automateの配置は[配置手順](deployment/README.md)を参照。

## 画面の確認内容

| 学生用SPFx・スマホ | 職員用Power Apps・PC |
| --- | --- |
| 学校メールの必須登録 | 開閉できる左側メニュー |
| 通常品の一覧・詳細・条件検索 | 拾得物登録・編集・保管中一覧 |
| 「紛失した物」で紛失申告・候補・受取予定をまとめて確認 | 学生の紛失申告の確認 |
| 新着案内・貴重品の個別案内 | 貴重品の現物を確認して本人へ案内 |
| 任意の特徴入力・受取申出・取り下げ | 「受取対応」で学籍番号・メール・受付番号から検索 |
| 受取窓口・受取番号・返却履歴 | 本人確認後の手動返却・来訪者への直接返却 |
| 任意の拾得物届け出・本人の届け出履歴 | 返却記録の訂正、一括移管、メール送信状況 |

- QR・写真は扱わない。本人確認は職員が対面で行い、確認チェック後に返却を記録する。
- 色は複数選択。選択色の**どれか1色**が共通すれば検索・新着照合の対象になる。既存の単色データも読める。
- 保管場所は公開し、長い名称も折り返す。職員設定の窓口を次回登録と一覧・受け取り申し込みの絞り込み初期値にする。全窓口にも切り替え可能。
- 特徴は任意入力。学生の本人確認用特徴、内部メモ、連絡先は公開用リストへ複製しない。
- 公開可否は品物の種類で自動決定せず、職員が拾得物ごとに判断する。非公開品の個別案内では受取窓口と一般的な連絡文だけを本人へ示す。
- 条件保存時には既存品を照合しない。新しい拾得物登録時に、先に保存されていた条件を照合する。通知では紛失開始日以降の拾得物を対象にする。
- 返却時は既存の `Status / ReturnRecipientEmail / ReturnedAt / ReturnedByEmail` を更新。競合はSharePointのETagで検出する。
- 公開・通知の更新に失敗しても主記録は残し、画面に保存済みと再同期の案内を表示する。再同期では通知を重複作成しない。
- 学生の拾得物登録は必須ではない。学生が登録する場合は現物を窓口へ届けてから。メールは自動記録し、お礼の受信チェックは初期オン・不要ならオフ。職員も登録でき、希望者だけ拾得者メールを任意登録する。返却後のお礼は固定メールのみ。自由記述・匿名公開は廃止し、旧投稿データは非公開で保持する。更新の反映手順は[学生拾得物登録とお礼](../lost-found-verification/2026-09-27_学生拾得物登録とお礼.md)を参照（未配置）。

学生側は「紛失した物」の1件を「探し中 → 候補あり → 受け取り予定 → 受け取り済み」で管理する。公開一覧から直接申し込む場合も、特徴の任意入力だけで紛失申告と受取申出を紐づけて登録し、最初から受け取り予定にする。拾得日・拾得場所は紛失した日・場所に流用しない。通知から申し込む場合は通知元の同じ記録と特徴を引き継ぐ。既存申告の選択・近い条件による自動紐づけは行わない。通知だけでは候補あり、承諾後に受け取り予定とする。「申し込みを取り消す」は登録を残し、「取り下げ」は登録と申し込みをまとめて終了する。画面復帰・同一ブラウザの別タブ保存・30秒間隔で表示を更新する。

学生画面のカードは白 `#FFFFFF`＋薄いグレー `#CCCCCC` の枠・角丸8px・ドロップシャドウなし。枠はPCで1px、スマホ（幅520px以下）で0.5px。スマホの選択チップ・建物選択・通常ボタンも細枠に揃える。検索・入力欄は `#F5F5F5`、補助文字は `#666666`。グレーはメルカリ公式Webの表示を参照し、カードは白と細枠のデザインに変更した。緑の操作色と職員画面は維持する。[確認方法と配色](../lost-found-verification/2026-09-27_学生画面の白とメルカリグレー.md)。

学生の拾得物登録は職員の登録と同じ分類・場所マスタを使う。親カテゴリ・細かい種類・色・キャンパスは横詰めチップ、建物は検索して選ぶ一覧。建物を選ぶと閉じ、選択中の名前を押すと変更できる。建物コードと任意の詳細場所は別々に保存し、職員の受領時に引き継ぐ。学生には公開判断・保管窓口・内部メモを出さない。[変更と確認](../lost-found-verification/2026-09-27_学生と職員の拾得物登録の統一.md)。

検証サイトに8リストと追加5列を作成済み。実際の `FoundItems` **13件（保管中11件）**を新しい読込処理で取得し、更新競合に使うETagも確認した。一時的な利用者設定データで作成・更新・古いETagの拒否・削除も実環境で確認済み。既存13件の拾得物レコードは変更していない。

**学生への公開は未実施。** 現在の検証アカウントでは、リスト権限設定がREST・Chromeの管理画面ともに拒否された。作成したリストのアクセス権はまだサイトからの継承状態。所有者による権限設定、アプリカタログへの配置、Power Automateの接続・有効化が残る。

Power Automate用の5つの定義（公開情報同期・非公開品の本人案内、メール送信、感謝の公開、Power Apps登録時の条件照合、返却反映）は `deployment/flows` に生成済みで、検証環境へ配置・有効化した。公開・非公開の切替による`LFPublicItems`の作成／削除、メールキューの`PENDING`から`SENT`への遷移を実環境で確認済み。**本番用の通知ごとの閲覧権限と、更新した職員アプリ本体の既存アプリへの反映は未完了。** 配置状況と残作業は[配置手順](deployment/README.md)を参照。

### 非公開品の受け取り案内（2026-09-28）

公開品・非公開品のお知らせを「通知日時 → 本人の申告名の候補見出し → 紛失登録の品名・登録日時 → 共通の本文 → 受取窓口 → 状態に応じた操作」にそろえる。同じ品名の申告でも登録日時で区別できる。未申込はどちらも「候補を確認」、申込済みは「受け取り予定を確認」。非公開品のみ「品物の詳細は窓口で確認してください。」を補足し、公開品の詳細確認と非公開品の窓口案内をそれぞれ開く。申告カードからの非公開案内は従来どおり「案内を確認」で開く。「受け取りを申し込む」で元の申告が受け取り予定になり、取消・再申込・返却後も本人の申告名を維持する。非公開原本の品名・色・特徴・場所は取得・表示しない。既存の汎用タイトルの申出も、RequestIdで紐づく本人の申告名を表示し、既存レコードを書き換えない。

ローカルの業務テスト・スマホ／PCのブラウザテストと本番ビルドで確認。SharePointへのこの版の反映は別途必要。

「候補あり」の申告は「候補を見る（○件）」を開くと、申告に紐づく候補がコンパクトな行で並ぶ。公開品は詳細確認から申し込み、非公開品は窓口の案内だけ表示して申し込む。同じ品物の通知は重複表示せず、公開候補が保管中でなくなったら表示から外す。

Playwrightでスマホの検索、職員の登録・本人確認・単件返却、学生の履歴まで確認する。ワークフローテストでは、色のOR照合、公開判断、利用者隔離、二重返却防止、訂正、申出なし返却、一括移管、部分失敗・ETag競合に加え、拾得者メールの有無と固定のお礼の重複防止を確認する。

自動テストは `npm run test:e2e` の実行時に内部用ハーネスを自動起動する。ダミー利用者、ブラウザ内Repository、職員画面の代替実装は `tests/support` と `tests/harness` に隔離しており、本番Webパーツの `src` には含めない。通常の画面確認にハーネスを使う必要はない。
